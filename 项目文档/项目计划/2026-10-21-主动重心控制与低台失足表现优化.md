## 一、确认结果与阶段边界

- 重心控制最终选择 B：普通幅度稳定，持续保持极限前倾或后仰，即使没有对手干扰，也可能逐渐失衡。此前讨论的“单独推满摇杆始终稳得住”方案已被用户更正，不进入实施。
- 场地选择 A：每人一座独立小站台；台面容纳正常站姿及重心调整，救身迈步容易踩空。
- 摔落选择 A：低台失足摔倒，台下有清楚可见的落地面。本阶段用作验证场地，后续地图设计允许改变台面尺寸、高度、布局及摔落形式。
- 正常倾身、极限倾身、扑空与过度后缩需要形成连续、可理解的风险变化；不把某个输入或技巧按键直接等同于判负。
- 沿用先迈步者负。迈步时裁决，踩空和落地展示后果；不改成掉下平台才输。
- 沿用左右手独立控制、合法手掌／前臂接触及胸腹禁触约束；键鼠、手柄均覆盖，本地双手柄左右分屏保持需求。
- 不新增蓄力按键、体力条或独立资源消耗系统。用户所述“蓄力猛推”在本阶段通过现有发力增长、身体投入和实际动量表达。
- 联网仍属于项目后续需求；本阶段不接入网络服务，不启动模型训练，不扩展正式地图系统或美术制作。

## 二、已确认玩法与表现

### 1. 主动倾身与恢复

普通幅度的前倾、后仰由脚踝、膝盖、髋部及躯干协调完成。双脚保持合理支撑，避免整体僵直倾倒或因轻微主动调整就很快触发迈步；松开或反向调整时平顺恢复。

持续极限倾身本身保留风险。身体应逐渐接近恢复边界，让玩家通过姿态和运动趋势感知危险并有机会回正；不能突然触发隐藏的必输倒计时，也不能在实际已经无法恢复时仍被自动救回。危险程度依据姿态、重心、速度趋势和实际支撑判断，不能仅以按键保持时长判负。

猛推扑空时，实际身体投入越深、前冲动量越大，越难收住；普通试探或及时收力应仍可能恢复。对手撤手只撤去接触支撑，不产生拉力，也不直接判攻击者失败。

后缩闪避在合理范围内可控；持续极限后仰、过度技巧后撤及对手追击可以叠加风险。现有技巧按键不因被触发就必然导致迈步。

主动控制能力增强必须同时回归“静止对手可以被有效推动”。支撑力、恢复力和关节驱动保持有限，不通过无限增大支撑、锁死脚或扩大判负边界掩盖问题。具体幅度、恢复速度和风险增长参数以现有配置为起点，经可重复验证及用户试玩调整，不将未经验证的数值写成已验收结论。

### 2. 两座独立低台

- 两名玩家各站一座台，保持面对面及正常合法接触距离；台沿和下方地面清楚可见。
- 台面应容纳双脚初始接触范围和正常重心动作，不应让角色一开始就悬空或碰到台沿。
- 前、后、侧向保护步均按实际方向和台面几何判断支撑。场地使救身迈步容易踩空，但不能强制所有迈步必定摔落，或把所有失败都播放成向后摔。
- 若保护步仍落在有效台面上，应如实落脚且保留已锁定的判负结果；据此调校台面与合理步幅，不能靠事后放大步幅保证坠落。
- 台下地面用于真实落地碰撞。禁止保留与台面等高的隐藏大地板，也不能让足部世界锚点或站姿驱动在离台后继续提供悬空支撑。
- 台面尺寸、高度、布局和出生位置集中配置；身体高度、落脚检测和镜头取景使用实际出生及支撑基准，避免写死世界坐标高度后妨碍地图变更。

### 3. 判负、摔落与重开

流程：准备及倒计时 → 对抗 → 迈步时唯一裁决 → 保护步／踩空 → 倾倒摔落及落地停留 → 完整结算与开放重开。

判负后停止双方推手、重心及技巧输入，不允许胜者继续施加主动推力。输家沿实际失衡方向完成动作；失去台面支撑后，解除相应足部约束并退出站立恢复，保留身体关节及合理姿态约束，依实际物理完成摔倒，不能继续执行旧版“迈步落地后恢复站姿”的固定流程。

胜者维持自然站立，不被结算时统一清空重心的操作突然拉倒。双人同一模拟步触发迈步仍判平局，可同时展示双方失足，结果不能被后续碰撞改写。

展示至少覆盖完整摔倒和短暂落地停留；现有约 3 秒门槛作为初始展示基准，不能计时一到就截断动作，也不能完全依赖刚体绝对静止导致永远无法重开。完成判断兼顾落地、动作阶段和合理的异常兜底；异常未落地时应可恢复对局并留下诊断，不伪造落地成功。

展示中提前按重开不截断动作，也不缓存为结束后自动重开。重开恢复人物、足部锚点、姿态驱动、碰撞、出生位置、计时及反馈状态。

### 4. 第一人称镜头与反馈

- 沿用双方第一人称及原有有限观察，胜者视角保持稳定，不切换外部胜利机位或强制追踪对手。
- 通过低台高度、双方距离和取景安排，让胜者能辨认踩空、身体下落和落地过程；同时检查全屏键鼠与双手柄左右分屏。
- 败者镜头跟随实际位置，但限制剧烈翻滚及突变；不能照搬倒地头部的全部旋转。镜头不反向控制身体或改变胜负。
- 沿用已认可的接触、声音和震动基础；踩空时不播放虚假的成功落脚声，落地反馈依据真实落地事件。
- 镜头舒适度、摔倒辨识度、音色和真实手柄震感需要真人试玩，不以自动测试通过代替主观验收。

## 六、验收矩阵与复核重点

| 场景 | 期望结果 | 验证方式 |
| --- | --- | --- |
| 无输入及普通幅度倾身 | 稳定站立；正常调整不轻易迈步；松开或反向操作可恢复 | PlayMode、真人试玩 |
| 持续极限前倾／后仰 | 可以逐渐失衡，危险有连续过程；及时回正有恢复机会 | 固定步输入序列、姿态与重心记录、试玩 |
| 试探扑空与猛推扑空 | 风险随实际投入及动量变化，不是撤手必输；无拉力 | 双方交互 PlayMode、试玩 |
| 合理后缩与过度后撤 | 正常闪避可控，过度动作或受追击可失衡；技巧键不直接判负 | PlayMode、键鼠及手柄试玩 |
| 静止对手及左右换边 | 合法推击仍能推动并判负；换边不改变规则 | 实际接触测试、双人试玩 |
| 台沿及前后侧向迈步 | 按真实支撑踩空或落脚；无隐藏地面及悬空支撑；不同方向不套同一后退动作 | 几何检测、PlayMode、画面检查 |
| 台高／台宽改变 | 相对高度、出生、支撑及镜头仍合理；不能沿用绝对高度阈值误判 | 两组不同几何配置 PlayMode |
| 双方同一步失败及落地后碰撞 | 平局或既定胜负只裁决一次，不被后续碰撞改写 | EditMode、PlayMode |
| 展示期间主动输入、提前重开 | 不再发力，不截断动作；重开须在开放后重新按键 | PlayMode、开发包自动验证 |
| 未落地、暂停、失焦或断连 | 无永久等待或残留反馈；恢复不改变既定结果，异常有诊断及恢复路径 | PlayMode、实际设备专项 |
| 摔落中镜头与实际落地反馈 | 赢家看得清，败者无剧烈旋转；踩空不播放成功落脚，落地反馈不重复 | 双视口渲染、开发包、主观试玩 |
| 连续多局及场景重载 | 人物、支撑锚点、驱动、碰撞、计时、镜头和反馈全部恢复 | PlayMode、开发包 |

最需复核的五类边界：输入快速反向造成姿态冲击；判负清空输入导致赢家失衡；离台后残留世界锚点或站姿支撑；台高变化使绝对高度判断失效；身体未完全静止导致结算卡住。上述边界分别纳入任务一、二、三及验收矩阵，不留作只靠人工猜测的情况。
