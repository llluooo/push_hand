## 目标与设计依据

在原有双手独立控制、双手柄第一人称左右分屏及准备倒计时基础上，建立关节结构可信的物理训练人偶，让收手、身体后缩、推空后的前冲惯性和恢复能力决定博弈。先交付可试玩物理系统，再开展身体协调与玩法调优首轮机器学习实验。

本文件合并本阶段设计与实施步骤；首版路线仍见 `2026-10-19-02-推手游戏搭建路线.md`。按项目约定，只维护这一份阶段计划，完成或受阻时统一写一次日志。

## 全局约束及已确认选择

- 沿用 Unity 2022.3.62f3c1、Built-in、Input System 1.7.0，不更换物理引擎或升级项目。原灰盒保留作对照。
- 使用 Unity 刚体、碰撞体、ConfigurableJoint 与有限驱动力。骨盆、腰胸、颈部和双侧肩、肘、腕、髋、膝、踝形成身体链；使用训练人偶外观，不引入正式人物美术。
- 只有手掌、前臂之间允许对抗传力；胸腹不作为合法推击目标，不通过躯干碰撞继续推动对手。首轮不新增胸腹犯规判分系统；以合法目标与动作范围表达规则。
- 手部自动对准可达的对方手掌或前臂，但限制距离、转向速度及关节范围。不能无限追踪或穿过身体。
- 收手可撤去接触支撑，不能产生吸力。接触分离后保留身体、手臂的惯性；有限平衡恢复允许及时救回，也允许过度前倾者迈步判负。
- WASD／左摇杆控制主要重心。鼠标左右键／左右扳机分别控制左右手，鼠标／右摇杆控制有限观察。
- Q／LB 触发双手收力后撤；E／RB 触发双手假推。一次按下执行一次完整技巧，恢复且松开后可再次触发，不设每局次数限制。双脚不主动后撤，挪脚仍判负。
- 保留加入、3/2/1、暂停、失焦／断连冻结、恢复、结果与重开。准备和暂停不得推进刚体；恢复保留速度，重开清除速度、技巧、接触及输入残留。
- 双方身体控制能力对称，每局模型和参数固定。机器学习改善协调并辅助评估，不替玩家决定技巧时机，不在对抗中悄悄改变规则。
- 训练与试玩记录保存在本地，不上传玩家数据。采集输入、姿态、速度、接触及结果，明确这些不是人体动作捕捉真值。
- 本轮不实现联网、正式人物美术、额外技巧或完整比赛比分；联网仍保留为首版后续需求。设计不假设 PhysX 跨机器确定性，后续联网应采用权威状态同步。
- 场景、预制体、参数和材质通过编辑器 API 生成，不手改序列化资产；不写入 Library、Temp、Logs、obj。

## 重点风险及对应验证

1. 撤手后仍被自动追踪：测试收回手臂能分离合法接触，禁止转为胸腹目标。
2. 物理暂停恢复丢失动量：冻结保存线速度、角速度，恢复还原；倒计时不漂移。
3. 技巧按住或帧率差异导致连发：输入边沿缓存到固定步，恢复前不再次触发，未松开不重触发。
4. 双方同时失衡或更新顺序影响结果：同一物理步先收集双方状态再一次裁决；同一步为平局。
5. 模型利用模拟漏洞：留出扰动、动作时序与双方换边评估；未优于基线的模型不默认启用。
