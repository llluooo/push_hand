# 推手核心灰盒试玩说明

日期：2026-10-19。目标平台：Windows x64。

2026-10-20 的受控物理人偶升级采用独立原型，见 `物理原型试玩与验证说明.md`。独立物理场景、人偶和 `Builds/Physical` 试玩包已生成，原生测试通过；训练按用户安排后续跟进。本说明仍描述旧灰盒，新物理玩法的真实手感待用户试玩验收。

## 打开与开始

- 直接运行 `Builds/Windows/PushHandsGreybox.exe`。分享试玩包时需保留整个 Windows 文件夹，不能只复制 exe。
- 在 Unity 2022.3.62f3c1 中，选择菜单“推手 → 打开灰盒场景”，再点击运行。场景为 `Assets/_Project/Scenes/PushHandsGreybox.unity`。
- 同机正式对抗使用两只手柄。两人分别按各自的菜单键（Start / Options）加入，再按任一已加入手柄的菜单键开始。
- 玩家一在左屏、玩家二在右屏，各自为第一人称。默认面向对手，观察有角度限制。

## 手柄操作

| 操作 | 按键 |
| --- | --- |
| 左手推掌 | 按住左扳机，按压程度决定目标力度 |
| 右手推掌 | 按住右扳机 |
| 单手收回 | 松开对应扳机 |
| 身体重心 | 左摇杆 |
| 有限范围观察 | 右摇杆 |
| 开始、暂停、继续、结果后重开 | 菜单键 |

两只手分别伸出、收回和恢复，共享身体发力上限。手未接触对方时没有接触推力，但伸手发力会带来自身前倾。通过重心与发力时机对抗，持续失衡后会触发不可撤销的保护性迈步，迈步者判负；同一模拟步双方迈步为平局。

断连或窗口失焦时冻结对抗。重新连接后按菜单键继续；若换用另一只手柄，先按菜单键补位，再按一次继续。继续后需要松开扳机、左摇杆回中，再重新发力，避免恢复瞬间误推。

## 键鼠开发验证

在等待、就绪、暂停或结果阶段按 F1，切换到单人开发验证；正在对抗时先按 Esc 暂停。左屏由键鼠控制，右屏是保持中立的测试靶，不是 AI，也不属于同机双人键鼠模式。

| 操作 | 按键 |
| --- | --- |
| 左右手推掌、收回 | 鼠标左右键按住、松开 |
| 重心 | WASD |
| 观察 | 鼠标移动 |
| 开始、暂停、继续、重开 | Enter |
| 暂停并释放鼠标 | Esc |
| 退出程序 | Alt+F4 |

## 调试与调参

- F3 切换重心位置、预测趋势、失衡累计与双手动作状态。编辑器 Scene 视图启用 Gizmos 可查看支撑边界、重心和趋势线。
- 参数资源：`Assets/_Project/Configs/GreyboxConfig.asset`。距离单位为米、力量为牛顿、时间为秒。
- 固定步长为 0.02 秒，默认持续失衡门槛 0.25 秒，观察限制为左右各 35°、上下各 20°。
- 本次是受控平衡近似与程序姿态的灰盒，力量、恢复能力和动作时间仍需两人试玩调校，不代表完整人体力学或最终动作品质。
- “生成或重建灰盒”会覆盖自有原型场景和角色模板，保留参数资源，不覆盖 SampleScene；手工修改原型前先保存版本。

## 已验证与待验收

- Edit Mode：18 项通过，覆盖稳定与失衡恢复、趋势判定、同一步平局、唯一裁决、接触反作用、独立双手、重置、固定步分组一致性、设备绑定与隔离、断连替换、扳机力度、禁用设备及键鼠映射。
- Play Mode：4 项通过，覆盖分屏和中文资源引用、迈步与重置、初次接触时掌心贴合、失焦后保持冻结直到显式恢复。
- Windows x64 开发包干净构建成功，零错误、零警告；两只虚拟手柄可通过实际独立程序完成加入、开始、推掌和唯一判负。两种显示帧率下结果一致；这不是两人真实手柄试玩。
- 真实双手柄的手感、不同品牌驱动、插拔重连、视角舒适性与玩法平衡仍待现场验收。联网、比分、正式比赛流程、美术和音效在后续阶段实现。

测试结果与截图保存在忽略版本管理的 `Artifacts/Verification`，构建输出在 `Builds/Windows`。编辑器自动任务可用 `Tools/Invoke-EditorJob.ps1` 调用；独立包自动试玩可用 `Tools/Invoke-PlayerSmoke.ps1 -FrameRate 30` 或 `-FrameRate 144` 复现，会显示临时游戏窗口并自动退出。

## 字体与资源来源

中文界面使用 Noto Sans SC 的常规字重子集，重命名为 PushHands UI，来源及 OFL 许可证在 `Assets/_Project/Art/Fonts`。TMP 基础资源来自工程已有的 TextMeshPro 3.0.7；迁入自有资源目录后，着色器中的 TMP 本地包含路径改为明确项目路径。开发包内 `ThirdPartyNotices` 保留字体许可文件。
