# 推手核心灰盒搭建汇总

日期：2026-10-19。范围：本轮初步工程搭建与验证。状态：工程、规则、场景及开发包已实现并完成自动验证；真实双手柄试玩待验收。

## 最终安排与实现

- 按用户确认的“可试玩核心灰盒”实施，沿用 Unity 2022.3.62f3c1、Built-in，不重新创建或升级工程。
- 通过 Unity Package Manager 安装并锁定 Input System 1.7.0，通过编辑器接口启用新输入系统。没有引入网络、动画或其他玩法框架。
- 建立本地 Git，基线提交 `8bb160d`，在 `feature/push-hands-greybox` 原目录分支实施，无远程仓库。首次工程无仓库，本次不复制另一份工程或生成目录。
- 自有资源置于 `Assets/_Project`；通过 Editor API 生成独立灰盒场景、角色模板、参数资源、材质和分屏界面，保留 SampleScene 和 AGENTS.md。
- 实现双手柄独立加入与绑定、左右扳机力度、重心与观察控制、断连冻结和补位、恢复时松手保护；提供 F1 单人键鼠开发验证和 F3 调试显示。
- 输入与模拟分离，0.02 秒固定步计算接触、双向反作用、共享发力约束、受控平衡及预测重心趋势。双手分别伸出、收回和恢复。
- 持续失衡默认 0.25 秒后提交保护性迈步；同一步双方失败为平局，胜负唯一裁决。迈步驱动脚、躯干和视点，结束后双手自然收回。
- 实现等待、开始、对抗、结果、重开，以及暂停、失焦冻结和手动恢复；本次不加入联网、正式比分或完整比赛流程。
- 中文采用 Noto Sans SC 的 OFL 常规字重子集，重命名为 PushHands UI；TMP 资源来自原有 3.0.7 包，许可证随 Windows 包附带。

## 环境问题与处理

- 沙箱内启动 Unity 返回 140063，且进程列表未显示已有交互式编辑器。正常本机执行后发现同工程占用，停止重复批处理启动，改用工程内固定白名单编辑器任务工具。
- 原编辑器在输入设置切换后卡于 `Application.Shutdown.CleanupEngine`。首次强关请求被自动审批拒绝，原因是可能丢失未保存工作；用户随后明确确认无未保存工作并允许关闭重启，才执行重启。验证结束后恢复交互式编辑器并打开灰盒场景。
- TMP 3.0.7 源码没有新版技能提及的 `ImportResources` 方法，采用该包自身使用的非交互 `AssetDatabase.ImportPackage` 接口导入必要资源。
- 系统动态字体无法被当前 TMP 读取，已以附开放许可的字体子集修复。资源迁移引发旧相对包含路径的着色器报错，已改为明确项目路径并完成零错误干净构建。
- 无图形验证出现环境探针警告，最终改用实际 D3D11 图形后端验证。自动试玩首帧初始化曾跳过定时输入窗口，已改为按真实对局状态推进；初期失败报告留在 Artifacts 供排查。
