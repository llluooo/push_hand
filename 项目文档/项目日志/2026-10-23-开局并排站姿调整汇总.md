## 最终决定与主要改动

- 双方各自左右脚横向并排、脚尖朝向对手；移除 0.11 米前后错步，保留 0.30 米脚中心横向间距。
- 前后支撑区由约 [-0.160, 0.210] 米收至 [-0.105, 0.155] 米，深度由 0.37 米收至 0.26 米；不以隐藏边界维持原错步稳定性。
- 修改人偶创建入口，并通过 Unity Editor API 定向更新原物理场景及 Fighter0、Fighter1 预制体的足、小腿、关节参考轴与锚点、保存的重开姿态。资源对象 ID 集合一致，场地、出生间距及原相机配置保留。
- 新增“推手/物理人偶/更新开局并排站姿”编辑器入口，并接入原工程任务脚本；迁移只识别旧默认参数，保留另行自定义的数值。
- 脚位收窄后重新调校普通主动倾身和保护步，保留静止稳定、普通倾身可恢复、静止对手可被推动、极限动作有失衡风险等行为。

## 排查与修正

- 先补充五项站姿检查，实际得到 44 通过、5 失败，确认程序创建、两个预制体和场景均存在原错步。
- 初次迁移暴露出编辑状态只写 Rigidbody 位姿未可靠保存 Transform 的问题，修正为显式同步可见 Transform、刚体和初始姿态，并补充可见脚位、踝锚点及膝参考轴检查。
- 直接沿用旧倾身幅度时，普通前倾、部分换边推击与失足回归失败；按实际支撑收窄调校，而非扩大判定边界。最终静止、普通倾身、短按收回、反向调整、双方换边推击及前后失足均通过。
- 主动迎推可能通过真实接触反作用更早逼进攻者迈步。原测试仅比较任一方首次失败的时间，会将提前反制获胜记作防守变差；现区分双方结果，要求迎推准备不自行迈步，并验证防守确实延长反应时间或在自己未迈步时反制获胜，保留接触与反应过程检查。
- 热重载后缓存有效标记可能残留，而字典及驱动缓存已失效，导致重新测试场景时 ResetPose 空引用；将 cached 标记设为 System.NonSerialized，保证重载后重新建立缓存。
- 上述缓存标记曾因遗漏 System 命名空间引发编译失败。修正后重新运行最终完整检查；编译失败期间旧程序集的结果不作为最终通过证据。
- 备用源码编译脚本原有 EditMode UnityEditor 引用不足，未据此宣称通过；最终以实际编辑器编译、测试及 Windows 构建验证为准。外部进程枚举亦未作为编辑器连接证据，实际使用已有编辑器任务入口写回状态。
