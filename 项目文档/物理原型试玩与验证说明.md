# 物理原型试玩与验证说明

## 2026-10-21～2026-10-23 主动重心与低台失足（physical-v4，当前试玩版本）

本版在已认可的推动反馈基础上，调整主动倾身的建立速度并接入独立低台、真实失足摔倒。主观手感、镜头舒适度和真实双手柄仍待用户试玩；具体自动验证结果以当前阶段计划的实施记录为准。

- 打开 `Assets/_Project/Scenes/PushHandsPhysical.unity`，点击 Play → F1 → Enter；等待 3/2/1，并先松开推掌及重心输入。Windows 最新实验包仍使用 `Builds/Physical/PushHandsPhysical.exe`。
- 普通幅度倾身可以维持；键鼠短按 W／S 后松开，应能收回。手柄用左摇杆中等幅度比较稳定。持续满幅前倾／后仰仍会逐渐失衡，不能把 W／S 当作无代价的永久姿态。
- 保持 F2 自动轻推关闭，检查双手推掌配合前压仍能推动静止对手；再比较短促试探、持续投入、扑空后收回和 Q／LB 后撤。提前撤手只卸去接触，不产生吸力；过度动作可能让自己先迈步。
- 两人各站一座小台。按 10 月 23 日前后失足的试玩反馈，当前默认台面为 0.46×0.38 米、落差 0.55 米，台面中心相对角色站位向前偏 0.02 米；相较上一版保留前沿位置、收进后沿 4 厘米，正常站位及双方接触距离保持一致。迈步时即锁定胜负，随后按实际支撑完成落脚或踩空摔倒，不等掉到地面才判负。脚仍搭在台沿时可以先落脚，也可能随后滑落；不强制每次失败都摔倒。当前小台已分别验证持续前倾、持续后仰、静止对手被推退后的实际失足，后续地图仍可调整几何。
- 判负后停止主动发力，仍可用鼠标／右摇杆观察。展示覆盖身体摔倒及短暂落地停留，至少保留原有约 3 秒；看到重开提示后再重新按 Enter／菜单键，提前按键不截断或缓存。
- 镜头默认垂直视野 86 度、初始俯角 20 度，仍为原第一人称；倒地时保持稳定观察方向并排除自身肩胸遮挡，另一玩家仍看见完整倒地身体。可适当向下观察，重点反馈是否看清失足过程、是否晕眩或穿模。
- 实际摔落接地触发落地声和短促震动；躯干摔倒后由台面真实承托也可完成展示，擦碰台侧不算承托。踩空不播放成功保护步落脚。暂停、失焦和断连会冻结展示并清理反馈，恢复继续动作；重开应恢复站姿、脚部支撑、身体可见性及全部状态。
- 极端情况下动作超过 8 秒仍未完成，会记录超时警告并开放重开；这是异常恢复，不能视为正常落地或通过验收。

场地和重心参数位于 `Assets/_Project/Configs/PhysicalConfig.asset`。调整 `PlatformSize`、`PlatformForwardOffset`、`PlatformHeight` 或 `Spacing` 后，退出 Play、保存当前修改，再使用“推手 → 物理人偶 → 更新独立低台与重心参数”同步场景。`PlatformForwardOffset` 控制台面相对正常站位的前后偏移；场景中的 `SpawnOffsets` 以平台旋转为参照、用米保存出生偏移，不随平台尺寸缩放。该入口定向更新原场景，不需要重新生成整个人偶；后续地图可更换几何和落地面，再复核支撑、出生位置和取景。

本版记录／模型协议为 physical-v4，旧模型不能直接接入。正式训练继续暂停，`Training/physical_training.py` 仍对应历史 v3，需在后续训练专项适配场地和当前规则后再使用；下方旧训练说明保留作历史参考，不代表 v4 已完成训练准备或评估。

建议试玩顺序：站立和短按回收 → 持续极限倾身 → 静止对手受推 → 撤手扑空／后撤 → 观察完整摔倒 → 暂停恢复 → 连续重开。真实双手柄另外检查左右屏输入隔离、震感及断连恢复。

## 生成与打开

1. 使用原 Unity 2022.3.62f3c1 打开本工程，等待脚本导入并检查 Console。

## 操作

| 动作 | 双手柄模式 | 键鼠开发模式 |
| --- | --- | --- |
| 加入、开始、暂停、继续、结果后重开 | 各自菜单键 | F1 切换键鼠；Enter 操作流程 |
| 左／右手推掌 | 左／右扳机 | 鼠标左／右键 |

| 重心 | 左摇杆 | WASD |
| 观察 | 右摇杆 | 鼠标移动 |
| 双手收力后撤 | LB | Q |
| 双手假推 | RB | E |
| 暂停 | 菜单键 | Esc |

两人加入后，再按一次菜单键才进入 3/2/1；恢复和重开同样倒计时。准备时冻结身体；恢复还原物理速度，重开清空速度与技巧状态。进入对抗后双手推力和重心操作先回中，技巧键先松开。

技巧是按一次执行一套动作，按住不重复；在恢复期间新按的技巧不排队。后撤通过身体与手臂完成，不能主动挪脚。胸腹不作为推力接触目标，不新增胸腹犯规判分。

键鼠模式仅用于开发：右侧对手显式维持轻推，便于检验真实手部接触；它不是学习 AI，也不代表联网或同机双人键鼠。本地正式双人仍使用两只手柄。

## 必须在真实物理中验证的场景

- 空闲站立 5 秒以上，无发力时不自行倒下；脚部支撑不是无限位置锁定。
- 双方推掌时，手掌／前臂确实碰撞并传力；躯干、头部和腿之间不会形成对抗推力。
- 一方撤手后，另一方不能无限追踪或改推胸腹；手掌不穿过躯干，手臂不反关节。
- 持续前推时突然失去接触，身体保留前冲速度；适量发力可以恢复，明显过度前倾可能提交保护步并判负。
- Q／LB 后撤与 E／RB 假推有完整动作及恢复，不产生瞬移或吸力。
- 暂停、失焦、断连与准备中没有漂移；恢复保留惯性，重开恢复初始站姿与手脚状态。
- 第一人称两侧都能看清自己的手与对方接触，头部不遮挡；身体关节和近距离镜头没有明显抖动或穿模。

本次已自动验证站立、真实接触后撤分离、冻结恢复和重开；已查看编辑器捕获的初始人偶全景与第一人称视图。这些检查不替代两位玩家对操作手感、持续对抗、分屏镜头及平衡性的试玩反馈。

## 本地记录与学习实验

F4 显式开关记录，不自动上传。编辑器记录位于 `Artifacts/PhysicalRecords`，独立程序记录位于 Unity 的 `Application.persistentDataPath/PhysicalRecords`，启动记录时 Console 会打印完整路径。JSONL 包含版本、配置快照、回合、时间步、双方输入、重心速度、接触、技巧和结果，不记录账号或设备标识。

训练方法是标准库实现的交叉熵搜索：学习 10 维观察到 2 维协调修正的线性残差策略，共 22 个参数；输出经限幅，最多修改 2 度姿态目标。随后独立搜索手臂驱动、恢复增益、前倾承诺的三个小范围参数。不需要安装 PyTorch、ML-Agents 或升级 Python；不是全身神经运动控制系统。

真实物理包存在后，在项目根目录运行：

```powershell
python Training/physical_training.py --player Builds/Physical/PushHandsPhysical.exe --output Artifacts/PhysicalLearning
```

首轮默认 3 代、每代 8 个候选；双方换边，包含站立扰动、推收、假推和额外留出场景。每批通过独立程序执行真实 `Physics.Simulate`，保留请求、响应与 Unity 日志。没有物理包或执行受阻时写 `blocked.json` 并以退出码 2 结束，不生成虚构模型成绩。

使用玩家记录辅助实验可追加 `--trace <文件> --episode 0`。这里只重放输入序列，身体从标准站姿开始；不是精确重现录制时的全部物理状态，不是模仿真实人体动作。训练输入不进入留出评估，回合不能隐式拼接，非 0.01 秒轨迹需显式重采样。

模型晋级要求留出损失改善至少 2%、失败次数不增加、最低骨盆高度不低于 0.70 米，并通过站立、合法接触、撤手分离和前冲惯性场景。达到门槛的 `body-policy.json` 才会标记 validated；仍需完整回归和人工试玩后，才能作为 TextAsset 导入并赋给 PhysicalMatch 的 ValidatedPolicy。双方共用同一模型；本轮没有自动启用模型，也不自动替换比赛参数。

调参建议与基线、留出结果保存到 `evaluation.json`。它是实验建议，不代表已验证游戏公平性，更不能取代两位玩家的试玩。
