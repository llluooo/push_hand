## 2026-10-20 推压与防守修正版（当前版本 physical-v3）

用户反馈稳定后推不动对手，本版已重新校准接触传力、主动重心与脚底支撑判定。2026-10-20 用户试玩确认“这版手感不错”，本阶段手感验收通过。

- 点击 Play → F1 → Enter，先保持 F2 对手自动推掌关闭。
- 鼠标左右键推压应让对手身体发生可见变化；配合 W 前压，或手柄双扳机配合左摇杆前压，可逼迫完全不操作的对手出保护步。

- F3 的“支撑”显示接触载荷所需的支撑位置，“推力”显示当前主动接触压力；地面调试边界来自实际脚掌投影。重心位置尚在边界内，仍可能因外力矩无法支撑而触发保护步。
- 失衡后应看到实际迈步，自动回归中足部位移约 22 厘米，不再只是原地判负。
- 最新完整原生 PlayMode 35 项、EditMode 37 项通过；Windows 开发包已更新，构建 0 错误、0 警告。当前手感已由玩家确认，真实双手柄与持续真人对抗仍待专项验证。

## 生成与打开

1. 使用原 Unity 2022.3.62f3c1 打开本工程，等待脚本导入并检查 Console。
2. 独立中文字体源已准备在 `Assets/_Project/Art/PhysicalFonts`；需要重生成时运行 `python Tools/PrepareUIFont.py --physical`。旧灰盒字体不被覆盖。
3. 保存当前已修改场景，选择“推手 → 物理人偶 → 生成独立物理原型”。该操作生成 `Assets/_Project/Scenes/PushHandsPhysical.unity`、独立人偶预制体、材质和参数资源，不覆盖旧灰盒，不改变原 Build Settings。
4. 选择“推手 → 物理人偶 → 打开物理原型”，点击运行。默认不启用任何未经评估的学习模型。

若 Console 有异常，先保留错误与堆栈；不得因为源码编译通过就跳过实际关节和场景检查。

## 操作

| 动作 | 双手柄模式 | 键鼠开发模式 |
| --- | --- | --- |
| 加入、开始、暂停、继续、结果后重开 | 各自菜单键 | F1 切换键鼠；Enter 操作流程 |
| 左／右手推掌 | 左／右扳机 | 鼠标左／右键 |
| 单手收回 | 松开对应扳机 | 松开对应鼠标键 |
| 重心 | 左摇杆 | WASD |
| 观察 | 右摇杆 | 鼠标移动 |
| 双手收力后撤 | LB | Q |
| 双手假推 | RB | E |
| 暂停 | 菜单键 | Esc |
| 调试重心、趋势、接触 | F3 | F3 |
| 开始／停止本地轨迹记录 | F4 | F4 |

两人加入后，再按一次菜单键才进入 3/2/1；恢复和重开同样倒计时。准备时冻结身体；恢复还原物理速度，重开清空速度与技巧状态。进入对抗后双手推力和重心操作先回中，技巧键先松开。

技巧是按一次执行一套动作，按住不重复；在恢复期间新按的技巧不排队。后撤通过身体与手臂完成，不能主动挪脚。胸腹不作为推力接触目标，不新增胸腹犯规判分。

键鼠模式仅用于开发：右侧对手显式维持轻推，便于检验真实手部接触；它不是学习 AI，也不代表联网或同机双人键鼠。本地正式双人仍使用两只手柄。

## 必须在真实物理中验证的场景

- 空闲站立 5 秒以上，无发力时不自行倒下；脚部支撑不是无限位置锁定。
- 双方推掌时，手掌／前臂确实碰撞并传力；躯干、头部和腿之间不会形成对抗推力。
- 一方撤手后，另一方不能无限追踪或改推胸腹；手掌不穿过躯干，手臂不反关节。
- 持续前推时突然失去接触，身体保留前冲速度；适量发力可以恢复，明显过度前倾可能提交保护步并判负。
- Q／LB 后撤与 E／RB 假推有完整动作及恢复，不产生瞬移或吸力。
- 暂停、失焦、断连与准备中没有漂移；恢复保留惯性，重开恢复初始站姿与手脚状态。
- 第一人称两侧都能看清自己的手与对方接触，头部不遮挡；身体关节和近距离镜头没有明显抖动或穿模。

本次已自动验证站立、真实接触后撤分离、冻结恢复和重开；已查看编辑器捕获的初始人偶全景与第一人称视图。这些检查不替代两位玩家对操作手感、持续对抗、分屏镜头及平衡性的试玩反馈。

## 本地记录与学习实验

F4 显式开关记录，不自动上传。编辑器记录位于 `Artifacts/PhysicalRecords`，独立程序记录位于 Unity 的 `Application.persistentDataPath/PhysicalRecords`，启动记录时 Console 会打印完整路径。JSONL 包含版本、配置快照、回合、时间步、双方输入、重心速度、接触、技巧和结果，不记录账号或设备标识。

训练方法是标准库实现的交叉熵搜索：学习 10 维观察到 2 维协调修正的线性残差策略，共 22 个参数；输出经限幅，最多修改 2 度姿态目标。随后独立搜索手臂驱动、恢复增益、前倾承诺的三个小范围参数。不需要安装 PyTorch、ML-Agents 或升级 Python；不是全身神经运动控制系统。

真实物理包存在后，在项目根目录运行：

```powershell
python Training/physical_training.py --player Builds/Physical/PushHandsPhysical.exe --output Artifacts/PhysicalLearning
```

首轮默认 3 代、每代 8 个候选；双方换边，包含站立扰动、推收、假推和额外留出场景。每批通过独立程序执行真实 `Physics.Simulate`，保留请求、响应与 Unity 日志。没有物理包或执行受阻时写 `blocked.json` 并以退出码 2 结束，不生成虚构模型成绩。

使用玩家记录辅助实验可追加 `--trace <文件> --episode 0`。这里只重放输入序列，身体从标准站姿开始；不是精确重现录制时的全部物理状态，不是模仿真实人体动作。训练输入不进入留出评估，回合不能隐式拼接，非 0.01 秒轨迹需显式重采样。

模型晋级要求留出损失改善至少 2%、失败次数不增加、最低骨盆高度不低于 0.70 米，并通过站立、合法接触、撤手分离和前冲惯性场景。达到门槛的 `body-policy.json` 才会标记 validated；仍需完整回归和人工试玩后，才能作为 TextAsset 导入并赋给 PhysicalMatch 的 ValidatedPolicy。双方共用同一模型；本轮没有自动启用模型，也不自动替换比赛参数。

调参建议与基线、留出结果保存到 `evaluation.json`。它是实验建议，不代表已验证游戏公平性，更不能取代两位玩家的试玩。
